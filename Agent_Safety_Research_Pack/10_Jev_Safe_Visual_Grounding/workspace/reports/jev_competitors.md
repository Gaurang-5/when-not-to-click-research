# Jev-specific competitor audit

Checked 17 October 2026; findings distinguish inspected methods from absence-of-evidence claims.

## Visual Jev

Guanxu Yu and Yuhang Yao, **Visual Jev: Accurate and Efficient Decisions from Shared Visual Context**, [arXiv:2609.25845v1](https://arxiv.org/abs/2609.25845), submitted 22 September 2026; retrieved history lists v1 only. No peer-reviewed venue verified. [Full methods and Appendix A](https://arxiv.org/html/2609.25845v1) were read. This is a Qwen3-VL-based system, not a native hosted Jev 1.14 experiment. It evaluates GQA, SNLI-VE, TextVQA and TallyQA, with parent-image split isolation and held-out calibration. Appendix A already compares confidence versus logistic gates using margin, entropy and answerability, temperature scaling, AURC and coverage at 5% risk. Evidence-region degradation and equal-area controls distinguish missing evidence from generic corruption. Extra sufficiency supervision detects missing evidence but does not improve decisions. Its image split and intervention shift are not unseen GUI application-template tests; it does not evaluate native Box plus presence/count on absent/ambiguous GUI targets. Its limitations include imperfect scene-graph evidence regions and limited backbone/task transfer. **Strong conceptual overlap: joint sufficiency gating and negative results cannot be claimed novel.**

## PixelJev

Xunlan Zhou, Xianliang Yang and Li Zhao, **From Text Decisions to Pixels: An Study of Jev-Style Visual Choice Model**, [arXiv:2609.29283v1](https://arxiv.org/abs/2609.29283), submitted 24 September 2026; history lists v1. No peer-reviewed venue verified. [Full paper](https://arxiv.org/html/2609.29283v1), especially §§4.5/6 and Appendices B/E/F, was inspected. PixelJev uses small open multimodal backbones and candidate-token probabilities, not native TypeSafe Jev. Seven evaluations cover recognition, transfer and multiple-choice VQA; calibration includes NLL, Brier, 15-bin ECE and selective risk. Source-temperature calibration need not improve target reliability. Appendix E explicitly proposes separating correctness, valid-candidate availability and evidence sufficiency, freezing rejection thresholds and testing shift at matched coverage. GUI action assessment is a research agenda, not a reported native Jev Box experiment. Candidate-set dependence and missing alternatives threaten probability interpretation. **The broad proposal is anticipated; a new contribution must be an executed, carefully controlled empirical result.**

## ImageJevBench Box v0.1

Independent repository benchmark by fstandhartinger / Benchmark Heaven, [method dated 14 October 2026](https://github.com/fstandhartinger/jevbench/blob/main/datasets/imagejev-box-v0.1/METHOD.md). Native `jev-1.14.0` boxes, IoU/Acc@.5/.75, ten-bin confidence ECE, latency and cost are already evaluated, including GUI screenshots. Therefore “first calibration of Jev boxes” is invalid. Public items were downloaded and parsed: 300 rows, with 200 photo, 50 document and 50 UI items; every row supplies one gold box. Method removes unresolved confusion rather than evaluating ambiguous rejection. It does not document an absent/ambiguous policy test or held-out application-template risk transfer. Its published image-size statement (256 minimum) conflicts with current official 280 minimum. [README](https://github.com/fstandhartinger/jevbench/blob/main/datasets/imagejev-box-v0.1/README.md) says 600 sealed; [merged PR 216](https://github.com/fstandhartinger/jevbench/pull/216) says 546. Treat sealed size as unresolved rather than selecting one. UI/document assets are CC BY 4.0; photos have per-item licenses. Reusing photos requires individual license checks. Public schema inspection alone is not independent image/annotation validation.

## Recent repository search and adjacent implementations

GitHub API inspection retrieved repository releases and 30 recent issues/PRs. [Latest listed release v1.4.2](https://github.com/fstandhartinger/jevbench/releases/tag/v1.4.2) was published 24 September; Box additions are newer than that release. PR 216 merged 15 October 2026. Recent issues include image-capable decision-model submissions; no complete absent/ambiguous native-Jev risk-transfer study was identified in this inspected window. This is a bounded search, not proof of priority.

[CUA-JEV](https://github.com/ZJU-REAL/CUA-JEV) explicitly states Jev selects constrained actions from structured adapters rather than interpreting screenshots. [GUI JEV Harness](https://github.com/ZihuaEvan/GUI_JEV) uses a separate vision model's tile descriptions, `NO_MATCH`, confidence/margin gates and recursive localization. Its independent OpenJev mode can process pixels directly. These are meaningful rejection/grounding prior implementations, but neither README establishes the exact native hosted Jev image-Noul/Choice/Box experiment. GUI JEV's statement that TypeSafe lacks image support is stale relative to current official docs.

## Defensible conclusion

**CONDITIONAL GO for a narrowly framed empirical evaluation; NO-GO for claiming a new three-output gate.** The strongest skeptical objection is that the API documentation supplies the mechanism, ImageJevBench supplies native Box/calibration evaluation, Visual Jev supplies joint sufficiency/selective prediction, and PixelJev explicitly anticipates testing unchanged thresholds under shift. The remaining candidate contribution is a transparent, nontrivial absent/ambiguous GUI benchmark plus independently validated held-out-template policy comparison. Its value depends on actual model data, annotation reliability, external screenshots/baselines and sufficient independent templates—not on renaming existing methods.
